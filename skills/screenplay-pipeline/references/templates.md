# Screenplay Pipeline — 템플릿 모음

## 목차
1. 트리트먼트 템플릿
2. 대본 포맷 상세 (변환기 문법)
3. 밈 패러디 가이드
4. IP 체크리스트 템플릿
5. 통합본 구조 + 떡밥 회수표 예시

---

## 1. 트리트먼트 템플릿

```markdown
# <작품명> — 1부 트리트먼트 (v1)

## 로그라인
(2~3문장. "누가 + 어떤 아이러니한 상황에 + 무엇이 문제인지")

## 세계관 / 네이밍
**<핵심 고유명사>: 「이름」**
- 이름의 유래와, 그것이 주제와 어떻게 연결되는지 (이름 자체가 복선이 되게)
- (후보안: A, B, C — 필요하면 교체)

**주인공 이름: <이름> (나이)**
- 이름에 얽힌 말장난/설정
- 성격 요약 (모순되는 두 얼굴이 있으면 코미디가 산다)

## 1부 씬 구성
### S1. <장면 제목>
- 비트 단위 요약 (웃긴 포인트는 "(웃긴 포인트 ①)" 식으로 태깅)
...

## 심어둔 떡밥 (2부용)
- 떡밥 하나당 한 줄: 무엇이 미해결인지 + 가능한 회수 방향 후보
```

원칙:
- 사용자 피치의 빈 조각은 직접 창작해 채우되, 답변에서 "내가 짠 부분"이라고 명시한다.
- 네이밍에는 반드시 이유를 단다. 이유 없는 이름은 사용자가 판단할 근거가 없다.
- 웃긴 포인트에는 번호 태그를 달아 사용자가 개별적으로 피드백할 수 있게 한다.

## 2. 대본 포맷 상세 (변환기 문법)

`scripts/make_script_docx.js`가 파싱하는 문법. 정확히 지켜야 Word가 예쁘게 나온다.

```markdown
# <작품명> — N부 대본 (vX)          ← 문서 제목 (2번째 #부터 새 페이지)

등장인물:                            ← 지문으로 렌더링됨 (자유 서술)
**이름** (나이, 성별) — 소개          ← 콜론이 없으면 대사가 아닌 지문 처리

---                                  ← 구분선

## S#1. 장소 (시간)                  ← 씬 헤딩

지문은 그냥 쓴다. 현재형. 여러 줄 가능.   ← 회색 이탤릭

**이름:** (지시문) 대사              ← 대사: 콜론이 ** 안에 있어야 함

### [몽타주 — 제목]                  ← 몽타주 헤딩
- 몽타주 항목                        ← 불릿

**— 1부 끝 —**                       ← 부 종료 마커 (가운데 정렬, "— ... —" 형태 필수)

## 심어둔 떡밥 (2부용)                ← 작업 노트: 반드시 종료 마커 "뒤"에
```

주의:
- 대사 판별 정규식은 `**이름:**` — 콜론이 볼드 밖에 있으면(`**이름**: 대사`) 지문으로 처리된다.
- 씬 번호는 부를 넘어 연속 (1부 S#1~9 → 2부 S#10~).
- 인물명에 지시 대상을 붙일 수 있다: `**남자:** (목소리만) ...`
- **떡밥 섹션은 부 종료 마커 뒤에 쓴다.** 통합본 추출 awk가 종료 마커에서 멈추기 때문에, 마커 뒤에 있어야 작업 노트가 통합본에서 자동 제외된다.

## 3. 밈 패러디 가이드

**철칙: 짤 이미지 삽입 금지 (방송사 저작권 + 초상권). 대사·상황 패러디로만.**
짧은 유행어 대사 패러디는 국내 예능/드라마 관행상 안전권이다.

배치 원칙:
- 부당 4~6개로 절제. 밈을 위해 장면을 만들지 말고, 이미 있는 장면의 캐릭터 일관성에 맞는 밈을 고른다.
- 가장 좋은 밈 배치는 **밈이 곧 캐릭터/플롯 장치가 되는 것** (예: "사딸라"를 동화 속 인물이 말하게 해서 현실 출신 떡밥으로 활용).
- 사용자가 짤을 던져주면 그 짤의 대사를 최우선으로 배치한다.

검증된 밈 풀 (출처 — 패러디 예):
- "이 차는 이제 제껍니다. 제 마음대로 팔 수 있는 겁니다" (MBC 뉴스) — 소유권 주장 장면
- "어이가 없네?" (베테랑) — 권위자가 반항에 얼어붙는 리액션
- "내가 왕이 될 상인가" (관상) — 얼굴 평가 장면
- "니가 가라 하와이" (친구) — 떠넘기기 거부
- "누구인가? 누가 기침(웃음)소리를 내었어" (태조왕건 궁예) — 권력자의 색출
- "중요한 건 꺾이지 않는 마음" (2022 유행어) — 비틀어서 신체 개그로
- "사딸라" (야인시대) — 가격 흥정 + 현대인 정체 떡밥
- "실화냐" — 비현실적 상황 리액션
- "묻고 더블로 가" (타짜) — 도박수 장면
- "형(네)이 왜 거기서 나와" (노래) — 의외의 등장

## 4. IP 체크리스트 템플릿

원작이 있는 작품(동화, 고전, 신화 등)일 때 생성. 파일명: `<원작IP>요소_체크리스트.md`

```markdown
# <IP사> 요소 안 씀 — IP 체크리스트

> 원칙: 원작(퍼블릭 도메인)은 자유, 각색자가 "추가한 표현"은 금지.
> 마지막 점검: <날짜> (<대상 문서> 기준)

## 1. 써도 되는 것 (퍼블릭 도메인)
- [x] 원작 스토리·모티프 (원작자, 연도 명기)

## 2. 금지 — 대본 단계
- [ ] ~~각색사 명칭 직접 언급~~ (현재: 없음 ✅)
- [ ] ~~각색사가 창작한 캐릭터·노래·장면~~ (현재: 없음 ✅)

## 3. 금지 — 영상화 단계
- [ ] 각색사 고유 비주얼(의상 색 조합, 건축 실루엣, 로고 서체) 복제 금지
- [ ] AI 이미지 생성 시 "<각색사> 스타일" 프롬프트 금지

## 4. 기타 타사 IP 주의
- [ ] 작품 내 고유명사의 기존 상표 충돌 (상업화 시 상표 검색)
- [ ] 밈/짤: 이미지 삽입 금지, 대사 패러디만

## 5. 배급 전 최종 게이트
- [ ] 법무 검토 / 상표 검색 / AI 비주얼 육안 대조

**한 줄 요약**: 이야기는 원작자 것(공짜), <상징 비주얼>은 각색사 것(금지).
```

새 부를 쓸 때마다 2번 섹션 기준으로 자체 검열하고 "마지막 점검" 날짜를 갱신한다.

## 5. 통합본 구조 + 떡밥 회수표 예시

```markdown
# <작품명> — 통합본 (1~N부 완결)

## 로그라인
## 등장인물 (전체)        ← 정체 반전이 있었으면 공개된 최종 정보로 작성
## 세계 규칙              ← 부마다 흩어진 규칙을 ①~⑤로 통합
## 배경

# 제1부 — <부제>
(1부 씬 구간)
# 제2부 — <부제>
...

# 부록 — 떡밥 회수표
- **<떡밥명>** — 심음: 1부 S#5 (...) → 회수: 3부 S#20 (...)
## 버전 기록
- 1부 v1.1 — ...
```

씬 구간 추출:
```bash
awk '/^## S#/{f=1} f{print} f && /^\*\*— .+ —\*\*$/{exit}' <N부_대본.md>
```

떡밥 회수표는 장식이 아니다 — 이후 씬을 수정할 때 "이 씬이 어떤 떡밥의 심기/회수 지점인지"
확인하는 안전망으로 쓴다. 회수표에 있는 씬을 고치면 반대쪽 지점도 함께 점검한다.
